RESPONSIBLE EXPERIMENTATION

Explore carefully. Build responsibly.

NEXORA is an experimental project, not a security certification. Its Linux foundation provides established system tools, but the project's own configuration, packages and desktop still require testing.

Use virtual machines for unfamiliar software and potentially disruptive experiments. Keep backups, review commands before running them, and avoid testing unknown code on important personal data or production systems.

BEGINNER-FRIENDLY · SAFETY FIRST

How to boot NEXORA OS

Start with a virtual machine. The ISO is a live system: it can be tried without installation, and changes are temporary. A NEXORA installer and USB persistence are not included.

Protect your files. Do not select your Windows disk in a VM or installer. No installer is present in this image. Writing an ISO to USB erases the selected USB drive.
A

RECOMMENDED

Try NEXORA in a virtual machine

Test the live desktop without changing your PC's boot setup. QEMU BIOS reaches the desktop. UEFI reaches Linux and starts XFCE processes, but its graphical output remains unverified; VirtualBox is a convenient beginner option, but is not itself tested here.

  1. Install VirtualBox from the official VirtualBox downloads page. Use the installer for your Windows host and keep its standard security prompts enabled.
  2. Create a new VM. Choose Linux and Debian (64-bit), with x86-64 architecture. Give it 4 GB RAM and 2 virtual CPUs for this test profile; these are tested settings, not published minimum requirements.
  3. Attach the ISO as an optical disc. In the VM's storage settings choose NexoraOS-0.1.0.iso from the downloaded files. Do not attach a host physical disk.
  4. Start the VM and select the normal live entry if a boot menu appears. Wait for the NEXORA XFCE desktop. You can use the file manager and terminal in the live session.
  5. Finish safely. Use the desktop's Log Out / Shut Down control, or close the VM and choose power off. The live session is non-persistent; unsaved files inside it are lost when it stops.

A virtual disk is not required to try the live image. If you add one for unrelated VM experiments, create a new disposable virtual disk in the VM application; never map a physical Windows disk.

B

OPTIONAL · DESTRUCTIVE TO THE USB

Create a bootable USB

The ISO is an isohybrid image with BIOS and x86-64 UEFI boot entries. It does not establish Secure Boot compatibility.

  1. Back up the USB. Writing an image erases all data on the selected USB. Copy anything important elsewhere and disconnect other removable drives to reduce selection mistakes.
  2. Download and open balenaEtcher from its official site, or use Rufus from rufus.ie.
  3. Select the ISO and carefully check the target device name and capacity. Choose only the USB drive. Do not choose an internal SSD/HDD.
  4. Write the image. Etcher writes the hybrid image directly. In Rufus, accept the recommended ISOHybrid/DD image-writing mode if prompted; do not manually repartition the image or choose a filesystem. BIOS and UEFI boot files are inside the ISO.
  5. Wait for verification from the writer, then safely eject the USB in Windows. Do not unplug it during writing.
C

LIVE TEST · NO INSTALLER

Boot from USB and return to Windows

Try NEXORA OS in live mode only. The image has no installer, and this guide does not ask you to change disks or firmware settings.

  1. Leave the USB connected and restart the PC. Immediately press the manufacturer's one-time boot-menu key (often F12, F11, Esc, or F9; check your device manual). Keys vary by manufacturer.
  2. Choose the USB entry. For UEFI systems, choose the entry explicitly labelled UEFI if both appear. If it fails, use the troubleshooting steps below; Secure Boot behavior has not been tested.
  3. Choose the normal NEXORA live entry. Use the system without opening a disk utility that writes changes. Hardware support varies; physical PC compatibility is unverified.
  4. To return to Windows, shut down from the live desktop, remove the USB when powered off, then start the PC and select Windows Boot Manager if needed. Do not change persistent boot order.
D

AFTER LIVE BOOT

Use the live desktop

  • The live desktop signs in automatically as the NEXORA live user; there is no account setup wizard in this build.
  • Use XFCE Settings for display, keyboard, time and desktop controls. In a VM, display and network devices are virtualized.
  • NetworkManager is included; connection availability depends on the hardware or VM network mode. Browser loading on physical Wi-Fi has not been certified.
  • Debian packages use APT, but installing packages in the live session is temporary and requires network access. There is no persistent storage configuration.
  • Install NEXORA OS: not available. Do not look for or expect an installer. A future installer must be separately implemented and tested on a disposable VM disk.

Troubleshooting

It returns to Windows or the USB is missing

Reopen the one-time boot menu and select the USB explicitly. Check that the image writer completed. If two USB entries appear, choose UEFI on an UEFI PC. Device keys differ; consult the manufacturer.

Black screen or graphics issue

Try the ISO's Debian live fail-safe entry if it appears. In a VM, enable its standard virtual graphics adapter and 3D acceleration only if needed. A VM test does not guarantee your physical GPU will work.

Secure Boot blocks startup

Secure Boot has not been verified for this image. Do not disable firmware security permanently. Check the project release notes for a signed build before changing Secure Boot settings.

Download is incomplete or checksum differs

Download again from the release folder and recalculate the SHA-256. Do not boot a file whose checksum does not match the published value.

How do I install or keep files between sessions?

This release is live-only. It has no installer and no tested persistence mode. Save needed work somewhere outside the live environment before shutting down.

Frequently asked questions

Does downloading install NEXORA?

No. The ISO is a bootable live image. Downloading only saves a file; booting it runs a temporary live system. This release does not install itself.

Is the ISO verified on real PCs?

BIOS was tested through the desktop in QEMU. In UEFI mode, Linux started and XFCE processes appeared, but the graphical output was not verified. Physical hardware, Secure Boot, Wi-Fi, Bluetooth, GPU acceleration and peripherals remain unverified.

Does the live session save my files?

No persistence is configured. Session changes are lost at shutdown. The host's disk is not modified automatically, but you should avoid writing to host drives from a live session.

What should I include in a bug report?

Include the ISO version, checksum, VM or PC model, BIOS/UEFI mode, exact error and steps to reproduce. Remove usernames, serial numbers, private files and credentials from logs or screenshots.

VERIFIED SCOPE

About and system requirements

This is an experimental Debian 13 live image for x86-64 PCs. The project has no published minimum physical-hardware requirements yet.

What is included

Debian GNU/Linux 13 (trixie), amd64 kernel, XFCE live desktop, NEXORA GTK shell, Firefox ESR, Thunar, terminal, developer tools and interactive diagnostics.

Test profile

QEMU test used 4 GiB RAM and 2 vCPUs. These settings are a practical VM test profile, not a guaranteed minimum or physical hardware certification.

Known limits

Live-only, no installer, no persistence. Secure Boot, physical GPU acceleration, Wi-Fi, audio devices and compatibility across PC models are unverified.

Recovery: Before using any recovery or partition tool, identify the target disk by model and capacity, back up important files, and do not write to a disk you are trying to recover. Recovery tools can cause data loss when misused.
